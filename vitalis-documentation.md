## 1. Стратегия объединения брендов

### Что было

Два отдельных проекта:

- **MediSynapse** — B2C-продукт для врачей и студентов. Три функции: клинические ответы, генерация статей, агрегация источников. Источники: PubMed, Medscape, Mayo Clinic, Cochrane, UpToDate. Палитра: голубой (#E8F4F8) + синий (#2563EB). Шрифт: Inter.
- **Vitalis** — B2B-платформа для клиник. Двухъядерная архитектура: GigaChat (РФ-протоколы, 152-ФЗ) + Claude (международные протоколы, обезличенный доступ). Сигнатурный элемент: интерактивная карточка протокола. Палитра: тёмно-синий (#0A1628) + изумрудный (#10B981). Шрифт: Playfair Display + Inter.

### Что стало

Один бренд **Vitalis** с четырьмя уровнями доступа (студент → врач → клиника → enterprise). MediSynapse-функции стали модулями внутри платформы.

### Почему это правильно

Два названия для одной аудитории создают когнитивную нагрузку: пользователь не понимает, где регистрироваться и чем продукты различаются. Vitalis как единый бренд решает три задачи:

1. Единая воронка: студент → ординатор → врач → клиника
2. Единое позиционирование: «AI-платформа клинических протоколов»
3. Единая кодовая база и дизайн-система

MediSynapse-функции не потеряны — они повысили статус из отдельного продукта в модули платформы (блок «Возможности»).

### Типографика

| Роль | Шрифт | Начертания | Зачем |
|---|---|---|---|
| Display (заголовки) | Playfair Display | 500, 700, 800 | Академическая весомость. Серифный шрифт для медицинского продукта — это не Montserrat/Poppins из каждого второго лендинга |

| Mono (коды, PMID) | JetBrains Mono | 400, 500 | Подчёркивает «данные, а не маркетинг». Используется для МКБ-кодов, PMID, eyebrow-надписей, бейджей технологий |

### Почему именно эта палитра

Тёмно-синий (#0A1628) — цвет институциональности и доверия. В медтехе это работает лучше, чем белый (слишком «потребительский») или чёрный (слишком «технический»). Изумрудный (#10B981) — буквальная отсылка к названию Vitalis (жизнь) + визуально ассоциируется с медицинским крестом. Фиолетовый (#A855F7) для Claude / международных протоколов — визуальное разделение: «фиолетовое = из-за рубежа», «синее = наше».

## 3. Структура страницы (12 блоков)

### 3.1. Header

- Sticky с blur-фоном (backdrop-filter)
- CTA-кнопка «Начать» появляется после 400px скролла (JS: `scrollY > 400`)
- Бургер-меню на экранах < 900px → полноэкранный оверлей
- Навигация: 6 якорных ссылок

### 3.2. Hero

Двухколоночная сетка:

**Левая часть:**
- Eyebrow: «AI-платформа для врачей и студентов»
- H1 с курсивным акцентом: «Vitalis / *Там где понимание становится практикой, а знания — стандартом*»
- Подзаголовок: ёмкое описание всех возможностей
- 4 бейджа технологий: GigaChat, Claude, Obsidian, 152-ФЗ
- Два CTA: «Начать бесплатно» (зелёный) + «Посмотреть карточку» (ghost)

**Правая часть:**
- Схема архитектуры в моноширинном стиле
- Показана полная цепочка: Obsidian Vault → FAISS/RAG → GigaChat → Карточка ⇄ Claude
- Бейдж безопасности: «🔒 Обезличенный запрос · без ПД · 152-ФЗ»

**Почему схема, а не скриншот:** скриншота продукта ещё нет, а абстрактная иллюстрация не несёт информации. Схема архитектуры решает две задачи — визуальное наполнение + объяснение устройства продукта.

### 3.3. Возможности (бывший MediSynapse)

Три карточки:
1. 🩺 Клинические ответы — PubMed, Medscape, клинрек РФ
2. 📝 Генерация статей — обзоры с PMID, списки литературы
3. 🔗 Агрегация источников — все базы в одном ответе

Каждая карточка заканчивается реальным примером запроса в моноширинном шрифте в кавычках. Цвета иконок совпадают с цветами архитектурных компонентов (синий → зелёный → фиолетовый) — сквозная визуальная система.

### 3.4. Как это работает

Двухчастный блок:

**Часть 1 — Проблема → Решение (3 строки):**
- ✕ Протокол — сотни страниц → ✓ Карточка с выжимкой
- ✕ РФ и ESC/AHA — разные окна → ✓ Две вкладки
- ✕ Зарубежные AI — риск 152-ФЗ → ✓ Обезличивание

Формат: горизонтальные строки с иконками и стрелкой →. На мобильных стрелка скрывается, контент вертикальный.

**Часть 2 — 3 шага:**
1. Врач задаёт вопрос (синий)
2. GigaChat + Obsidian Vault (зелёный)
3. Усилитель Claude (фиолетовый)

### 3.5. Интерактивная карточка протокола (СИГНАТУРНЫЙ ЭЛЕМЕНТ)

Самый важный блок. По нему посетитель понимает, что это реальный продукт.

**Структура:**
- Заголовок: I21 (код МКБ) + «Острый коронарный синдром»
- Кнопки: скачать, избранное, поделиться
- Две вкладки: РФ-рекомендации / Международные

**Вкладка «РФ» — алгоритм Д→Л→Р:**
- Три кликабельных шага (CSS class `.as.exp` для раскрытия)
- По умолчанию раскрыт первый (Диагностика)
- При клике: `max-height` анимация раскрывает детали (препараты в .dr чипах)
- Точки шагов масштабируются при hover (transform: scale(1.15) + box-shadow)
- Блок доказательности: «I A — сильная рекомендация»
- Источник: Минздрав РФ, 2024

**Вкладка «Международные» — анимация живого поиска:**
- Флаг `ia` (intl animated) — анимация запускается только один раз
- Таймлайн анимации:
  - 0 мс: пульсирующий фиолетовый индикатор (.pl с CSS animation)
  - 1200 мс: индикатор → зелёный, текст → «Анализ завершён · 3 источника»
  - 1600 мс: карточка ESC появляется (opacity 0→1, translateY)
  - 1900 мс: карточка AHA появляется
  - 2200 мс: блок отличий появляется
  - 2500–2900 мс: три ссылки PubMed каскадом
- Бейдж «🔒 Обезличенный запрос · без ПД» — юридическое успокоение

**Техническая реализация:**
- Переключение вкладок: `data-tab` атрибут + JS classList toggle
- Анимация появления панели: CSS `@keyframes pIn` (opacity + translateX)
- Раскрытие шагов: `max-height` transition (надёжнее чем height: auto)

### 3.7. Архитектура знаний (Obsidian) — НОВЫЙ БЛОК

Двухколоночная сетка:

**Левая колонка — вертикальный flow:**
1. 📓 Obsidian Vault → markdown-файлы, граф знаний
2. ⚡ Векторизация → LangChain → FAISS-индекс
3. 🧠 GigaChat RAG → контекст из vault в ответы

3. Публичная документация: API-справочник, гайды, changelog

**Для какой аудитории:** IT-директора и техруководители клиник. Для врачей этот блок может быть сложным — рекомендуется в будущем добавить toggle «для врачей / для IT».

## 4. Техническая реализация

### 4.1. Runtime-архитектура (актуально)

| Слой | Путь | Роль |
|---|---|---|
| Лендинг | `public/index.html` | Маркетинг, форма заявок |
| Кабинет | `web/app.html` | Клинический запрос, карточка ответа |
| Node | `server/index.js` | Статика, `POST /api/leads`, прокси `/api/ai` → Python |
| AI API | `backend/app/` | `GET /health`, `POST /ask`, RAG, веб-поиск, LLM |
| Vault | `vault/*.md` | Локальные протоколы для FAISS |

Поток запроса в кабинете:

1. Браузер → `POST /api/ai/ask` (Node)
2. Node проксирует на FastAPI `POST /ask`
3. Классификация намерения → RAG (`vault/`) → веб-поиск → контур `rf` / `intl` / `both`
4. Ответ очищается от имён провайдеров и отдаётся как карточка с вкладками

Режимы LLM: `LLM_MODE=mock` (без ключей) или `live` (GigaChat + DeepSeek). Веб-поиск по умолчанию: DuckDuckGo; опционально Serper / Tavily.

**Типичная ошибка:** `connect ECONNREFUSED 127.0.0.1:8000` — не запущен uvicorn. Статус кабинета `база undefined · веб undefined` означает, что `/api/ai/health` не получил ответ Python API.

Проверка здоровья:

- Node: `GET /api/health`
- Python напрямую: `GET http://127.0.0.1:8000/health`
- Через прокси: `GET /api/ai/health` → поля `vault_chunks`, `llm_mode`, `web_search`

### 4.2. Лендинг: размер и зависимости

- Основной лендинг в проде: `public/index.html` (исторический монофайл: `vitalis-unified.html`)
- Внешние зависимости: Google Fonts (3 шрифта)
- JavaScript: меню, табы, анимация, reveal, форма
- Без фреймворков, без сборки фронтенда

### CSS-архитектура

- CSS-переменные в `:root` для всех цветов, радиусов, теней
- Классы сокращены (.rv, .sh, .ey, .bd) для экономии объёма
- Media queries: 3 брейкпоинта (900px, 768px, 560px)
- Никаких `!important`

### JavaScript-компоненты

1. **Мобильное меню:** classList.add('open') / remove('open')
2. **Табы карточки:** data-tab + classList toggle + анимация intl-панели
3. **Раскрытие шагов алгоритма:** max-height transition
4. **Scroll reveal:** IntersectionObserver, threshold 0.08, rootMargin -30px
5. **Back-to-top:** scrollY > 500 → classList.toggle('show')
6. **Header CTA:** scrollY > 400 → display toggle
7. **FAQ аккордеон:** classList + maxHeight
8. **Форма:** клиентская валидация (имя, email regex, select) + `POST /api/leads`
9. **Reduced motion:** prefers-reduced-motion → все .rv получают .vis

### Accessibility

- `aria-label` на бургере и кнопке «наверх»
- Фокусные состояния через `:focus-visible` (браузерные дефолты)
- Контрастность текста: все пары проходят WCAG AA
- `prefers-reduced-motion` полностью поддерживается
