# Граница Life-OS / портал / Vitalis

## Итоговая схема

1. **Life-OS** собирает и отбирает источники, хранит заметки и кандидатов.
2. **Портал ДИС** публикует подготовленные статьи для чтения.
3. **Vitalis** индексирует только проверенные полные тексты клинических рекомендаций.

Статья портала, научная новость, обзор или заметка Life-OS не становится источником
RAG Vitalis. Это верно даже после медицинской редактуры и публикации.

## Что считается допустимым документом Vitalis

Markdown допускается в индекс только при одновременном выполнении трёх условий:

```yaml
document_type: clinical_guideline_full_text
content_scope: official_full_text_extracted
full_text_checked: true
```

Любой отсутствующий или иной маркер означает fail-closed: файл сохраняется на диске,
но не получает ни одного фрагмента в FAISS.

Библиографические карточки `clinical_guideline_metadata` нужны для обнаружения нужной
КР и проверки её версии. Они не индексируются и не подтверждают диагностику, лечение,
дозировки или уровень доказательности.

## Read-only inventory портала

Портал формирует закрытый инвентарный export:

```bash
python -m scripts.export_vitalis_lifeos \
  --output /private/path/lifeos-vitalis.json
```

Начиная со schema 2:

- `approved_records` всегда пуст;
- опубликованные статьи считаются `portal_articles_excluded`;
- raw Life-OS материалы перечисляются только как кандидаты без тела;
- export не меняет статус кандидата и не запускает импорт.

Этот файл нужен для аудита границы и не является пакетом знаний Vitalis.

## Сохранение прежних данных

Legacy Markdown-файлы ранее экспортированных статей не удаляются автоматически. Версия
индекса 2 исключает их по метаданным. Это позволяет сохранить трассируемость без риска
использования вторичного материала в клиническом ответе.

10 production-кандидатов Life-OS остаются в статусе `needs_medical_review`. Решение об
одобрении или отклонении не принимается автоматически и не связано с Vitalis.

## Проверка границы

```bash
PYTHONPATH=backend python -m unittest \
  backend/tests/test_vault_refresh.py \
  backend/tests/test_web_search_queries.py \
  backend/tests/test_search_integration.py \
  backend/tests/test_production_gate.py -v
```

Обязательный отрицательный тест: файл с
`document_type=reviewed_lifeos_article` остаётся на месте, но `VaultRAG.build()` не
создаёт из него фрагментов.

Обязательный положительный тест: полный текст КР находится по названию диагноза, коду
МКБ и произвольному клиническому запросу, а ответ содержит официальный URL и страницу.
