# Vitalis Medical AI — клиническая информация без долгого поиска

**Автор:** Степанов Д.А.  
**Репозиторий:** https://github.com/dimitry8st-prog/Vitalis-Medical-AI

## Что это за проект

Vitalis помогает врачу быстрее разобраться в клиническом вопросе. Вместо ручного просмотра десятков документов система собирает подходящие рекомендации, выделяет главное и показывает источники, по которым подготовлен ответ.

Пользователь может выбрать один из двух независимых режимов:

- **Российский** — поиск по клиническим рекомендациям Минздрава РФ, материалам профильных НМИЦ, профессиональных сообществ и медицинских журналов.
- **Международный** — поиск по руководствам и публикациям ведущих международных, европейских и американских организаций.

Vitalis не смешивает эти режимы без прямой просьбы. Если врачу нужно сравнение российских и международных подходов, система выводит их отдельно, чтобы различия были видны сразу.

## Как это работает

Сначала ассистент ищет информацию во внутренней базе знаний. Затем проверяет актуальные материалы через веб-поиск и формирует структурированный ответ со ссылками. Если источник недоступен или данных недостаточно, Vitalis прямо сообщает об ограничении, а не подменяет неизвестные сведения догадкой.

Сейчас ответы формирует DeepSeek. Для российского и международного режимов используются разные инструкции и разные приоритеты источников. Подключение GigaChat сохранено как отключённая возможность для дальнейшего развития.

## Для кого

- для практикующих врачей, которым нужна краткая выжимка по клиническому вопросу;
- для клиник, изучающих возможности справочного AI-инструмента;
- для демонстрации архитектуры медицинского RAG и контролируемого веб-поиска.

## Что умеет Vitalis

- ищет материалы по смыслу конкретного клинического вопроса;
- выделяет нозологию, код МКБ и цель запроса;
- показывает российские и международные данные раздельно;
- использует локальную базу знаний и актуальный веб-поиск;
- прикладывает источники и предупреждает, если проверка через веб не состоялась;
- не сохраняет найденные материалы в базу автоматически — сначала их проверяет человек;
- не выдаёт неподтверждённые ссылки и точные дозировки как достоверный факт.
- принимает синтетические или заранее обезличенные медицинские PDF, извлекает текст
  по страницам и формирует временный разбор с проверяемыми цитатами;
- отвечает на уточняющие вопросы только по загруженному документу и удаляет сессию
  вручную либо автоматически по TTL.

> **Текущий статус:** демонстрационный MVP для личной работы автора и проверки архитектуры.
>
> **Важно:** Vitalis — справочная система, а не автономный врач. Она не ставит диагноз, не назначает лечение и не заменяет клиническое решение специалиста.

С 16 октября 2026 года Vitalis доступен по HTTPS: [кабинет помощника](https://vitalis.st8dom.ru/app). Вход защищён паролем. Технический запуск и контрольный ответ проверены; клиническая точность и качество источников требуют отдельной оценки.

[Развёртывание, конфигурация, проверки и откат](docs/DEPLOYMENT_RU.md). Docker-конфигурация по умолчанию запускает mock-режим; live-ключ хранится отдельно на сервере.

## Для разработчиков

Лендинг + форма заявок + кабинет врача (MVP). **Нужны оба сервиса:** Node на `:3000` и Python AI API на `:8000`. Если Python не запущен, кабинет показывает `connect ECONNREFUSED 127.0.0.1:8000`.

| Часть | Технология | Порт |
|---|---|---|
| Лендинг, форма, прокси `/api/ai` | Node.js + Express | `3000` |
| AI / RAG / веб-поиск | Python + FastAPI + FAISS | `8000` |
| База знаний | `vault/` (Obsidian markdown) | — |

### Быстрый старт

Локально требуется Node.js 20+; контейнер использует Node.js 22.

```bash
cp .env.example .env
npm install && npm start
```

В **отдельном** терминале:

```bash
cd backend
py -3.12 -m venv .venv312
# Windows Git Bash:
.venv312/Scripts/python -m pip install -r requirements.txt
.venv312/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

PowerShell / cmd:

```bat
cd backend
py -3.12 -m venv .venv312
.venv312\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### Проверка

| URL | Что должно быть |
|---|---|
| http://localhost:3000/ | лендинг |
| http://localhost:3000/app | кабинет врача |
| http://localhost:3000/api/health | Node health |
| http://localhost:3000/api/ai/health | прокси → Python health |
| http://localhost:8000/docs | Swagger FastAPI |
| http://localhost:8000/health | `vault_chunks`, `llm_mode`, `web_search` |

Без ключей оставьте `LLM_MODE=mock` в `.env`. Для живых ответов установите `LLM_MODE=live` и добавьте `DEEPSEEK_API_KEY`. `GIGACHAT_ENABLED=false` оставляет GigaChat в режиме заглушки. По умолчанию `EVIDENCE_GATE_MODE=warn`: при сбое веб-поиска ответ сохраняется, но явно помечается как непроверенный. Режим `strict` можно включить отдельно.

### Контролируемое обновление знаний

Система не обучается на собственных ответах автоматически. После веб-поиска она выделяет новые источники как кандидаты со статусом `needs_review`. Владелец проверяет авторитетность, дату, применимость к выбранному контуру, противоречия, скрытые инструкции и чувствительные данные. Только одобренный материал преобразуется в канонический Markdown и загружается в RAG/Obsidian. Полный регламент: `docs/RAG_SOURCE_REVIEW.md`.


### Детальный веб-поиск

Поисковый слой работает независимо от RAG и строит запросы из текста клинического вопроса:

- выделяет нозологию, код МКБ и цель вопроса: диагностика, лечение, профилактика, классификация, прогноз или реабилитация;
- для российского контура отдельно ищет Рубрикатор Минздрава, материалы профильных НМИЦ, институтов и российских медицинских журналов;
- для международного контура ищет руководства WHO, NICE, европейских и американских профессиональных обществ;
- дополнительно проверяет PubMed и Europe PMC по рекомендациям, консенсусам, систематическим обзорам и метаанализам;
- при сбое основного поисковика использует резервный RSS-поиск;
- ранжирует выдачу по совпадению ключевых слов, авторитетности домена и актуальности публикации.

Международный контур дополнительно:

- фиксирует юрисдикцию и тип каждого источника;
- отделяет клинические руководства от регуляторных инструкций и исследований;
- для вопросов о лекарствах отдельно проверяет FDA/DailyMed, EMA и BNF;
- исключает неизвестные домены и российские документы из международной выдачи;
- загружает полный текст allowlist-источников и передаёт модели только ограниченный
  релевантный фрагмент;
- не переносит дозировки между странами без прямого подтверждения;
- не получает российский RAG-контекст даже при совместном режиме `both`.

Подробная схема: [docs/INTERNATIONAL_SEARCH.md](docs/INTERNATIONAL_SEARCH.md).

Периодическая литература и статьи дополняют, но не заменяют действующие клинические рекомендации.

### Vitalis Documents

В кабинете есть отдельная вкладка **«Разбор PDF»**. До обработки пользователь обязан
подтвердить, что документ синтетический или заранее обезличенный. Сервер проверяет
сигнатуру и структуру PDF, отклоняет JavaScript, активные действия, XFA и вложенные файлы,
ограничивает размер и число страниц, затем извлекает текст и выполняет дополнительное
обезличивание. Исходный PDF не добавляется в постоянное хранилище; временный upload
закрывается сразу после обработки.

По умолчанию `DOCUMENT_EXTERNAL_LLM_ENABLED=false`: доступно локальное детерминированное
извлечение. Передача обезличенного текста DeepSeek включается только отдельной переменной
окружения после проверки правовой схемы. При остаточных признаках персональных данных или
инструкциях внутри PDF внешний вызов блокируется независимо от настройки.

Содержание документа не смешивается с российскими или международными рекомендациями.
Каждый значимый факт содержит страницу и цитату, которая программно сверяется с
обезличенным текстом. Подробнее: [docs/VITALIS_DOCUMENTS.md](docs/VITALIS_DOCUMENTS.md).
